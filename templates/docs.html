Help & guide

Social media downloader guide

A straightforward guide to previewing public media links, choosing an output, and saving your file.

Open the downloader No account or API key required.

01 / Quick start

Download in four steps

  1. Copy a public link. Use the URL of one post or media item. Playlists and collections are not supported.
  2. Paste it into the downloader. The page previews a pasted link automatically; you can also select Preview link.
  3. Review the preview and options. The preview identifies the source platform and media type. Choose Auto for the recommended source-compatible option, MP3 for audio-only extraction, or MP4 for video.
  4. Select Download media. Follow the transfer status, then save the completed file from your browser.

02 / Output options

Formats and quality

  • Auto keeps the best compatible source format and is the recommended default.
  • Video / MP4 requests video output where the source supports it. Choose a preset up to 2160p or enter a custom maximum height from 144p to 4320p.
  • Audio / MP3 extracts an audio-only MP3 at 128, 192, 256, or 320 kbps when the source provides an audio track.
  • Quality choices are maximum targets, not guarantees. Available resolutions and bitrates depend on the original media and the selected platform.

Preview first when possible. The downloader identifies whether the link contains video, audio, or an image and can disable incompatible choices.

04 / Limits and privacy

What to know before downloading

  • Only download content you have permission to save, and follow the source site's terms and copyright rules.
  • Downloads are processed temporarily on the server and removed after transfer.
  • To show transfer progress, the browser temporarily buffers the file in memory, up to the server's configured {{ (max_download_bytes / 1048576)|round(0)|int }} MiB cap. Large files can use substantial memory.
  • Private or access-restricted posts may not work with this public-link workflow.

05 / HTTPS integration

Use the downloader on your own website

You can host this project behind your own HTTPS domain or link to this documentation from another site. For a secure integration, keep the downloader and the page that submits requests on the same origin, such as https://downloader.example.com. Cross-origin browser POSTs are rejected; there is no public CORS or API-key contract.

  1. Terminate TLS at a trusted proxy. Forward HTTPS traffic to Flask and overwrite Host, X-Forwarded-For, and X-Forwarded-Proto. Set TRUST_PROXY_HEADERS=1 only when direct access to Flask is blocked.
  2. Set the public origin. Configure PUBLIC_SITE_URL=https://your-domain.example without a path so canonical links, sitemap URLs, and social previews use your real site.
  3. Protect the session. Use SESSION_COOKIE_SECURE=1 in HTTPS production and keep FLASK_SECRET_KEY stable across workers or replicas. The page already sends its CSRF token and same-origin request signals.
  4. Reuse the guide safely. Link to /docs or copy its user-facing instructions with attribution. Do not copy secrets, cookie files, or server environment values into another site.

For a browser application on a different domain, use a server-side integration that you control or deploy this app under the same origin. Do not disable CSRF, add permissive CORS, or expose account cookies to make cross-origin requests work.

HTTPS request examples

# Check that your HTTPS deployment is ready
curl -fsS https://downloader.example.com/healthz

# Server-side metadata request (keep API calls on your own backend)
curl -fsS -X POST https://downloader.example.com/api/info \
  -H 'Accept: application/json' \
  --data-urlencode 'url=https://source.example/post/123' \
  --data-urlencode 'format=auto' \
  --data-urlencode 'quality=best'

The endpoint is rate-limited and accepts public media URLs only. Respect the source platform's terms, copyright rules, and any permissions required for the content.

06 / Troubleshooting

If a link does not work

  • Check that the URL is complete, public, and points to one media item.
  • Try previewing the link again. A source site may be temporarily unavailable or may block automated requests.
  • If the source no longer provides that media or the format is unavailable, try Auto or a different public link.
  • For a large file, check the displayed size limit and available browser memory.
